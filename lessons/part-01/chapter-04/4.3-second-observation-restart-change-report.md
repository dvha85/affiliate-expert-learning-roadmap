# Bài 4.3 — Second observation cycle, restart và change report

> **Mục tiêu:** chứng minh history capability của M01 hoạt động ngoài fixture: cùng một public subject có E1 observation tại `t1` và `t2`, cả hai sống sót qua restart, query/report deterministic và `UNCHANGED` được chấp nhận như outcome thật.

Đây là bài cuối của M01. Bạn chỉ mở nó **sau khi đã tự thử Checkpoint 3**: thu observation thật lần hai, append, restart và xem report trước khi đọc phần giải thích dài.

## 1. Vì sao M01 cần second real observation?

Unit test có thể chứng minh:

```text
append logic works
query logic works
delta logic works
```

Nhưng Reality gate cần chứng minh:

```text
history thực sự giữ hai E1 observations của cùng public subject ở hai thời điểm
```

Nếu chỉ copy fixture thành t2, bạn mới có engineering evidence, chưa có second market observation.

## 2. Reality minimum

M01 không bắt bạn quan sát lại cả 5 products.

Minimum:

```text
1 stable subject_id
+ E1 observation t1
+ E1 observation t2
+ observed_at khác nhau
+ provenance giữ nguyên
```

`UNCHANGED` hoàn toàn hợp lệ.

Ví dụ:

```text
t1 price = 299000
t2 price = 299000
```

không phải thất bại. Nó chứng minh source được quan sát hai lần và value không đổi trong hai snapshots đó.

## 3. Không copy last-known value để giả observation mới

Nếu tại `t2` source không truy cập được:

Sai:

```text
price_t2 = price_t1
```

rồi gọi đó là E1 observation mới.

Đúng:

```text
access failure / missing current evidence
```

History đáng tin ưu tiên “không biết” hơn fake continuity.

## 4. Restart proof là gì?

Flow:

```text
append t1
append t2
stop process
start process again
load history.jsonl
query subject
```

PASS khi:

```text
t1 vẫn tồn tại
t2 vẫn tồn tại
report không phụ thuộc memory cũ của process
```

Nếu restart làm history mất:

```text
Capability chưa durable
→ M01 chưa Operated
```

## 5. Change report phải truy được evidence

Report tốt nên cho reviewer thấy tối thiểu:

```text
subject_id
previous observation_id
current observation_id
previous observed_at
current observed_at
field delta states
freshness as_of + policy
source/evidence refs
```

Không cần production dashboard.

## 6. Deterministic report

Giữ cố định:

```text
history file
subject_id
as_of
freshness policy
code/formula version
```

Expected:

```text
same report semantics
```

Nếu report khác do hidden wall clock hoặc unstable ordering, phải sửa trước M01 PASS.

## 7. No-change cycle

Một cycle bắt buộc nên chứng minh:

```text
same observed value at t1/t2
→ UNCHANGED
```

Điều này bảo vệ khỏi anti-pattern:

```text
“không có change nên history vô ích”
```

History còn chứng minh **đã quan sát lại**.

## 8. Changed/missing fixture cycle

Không phụ thuộc thị trường phải tình cờ đổi.

Dùng fixture được gắn nhãn rõ để test:

```text
CHANGED
MISSING_CURRENT
MISSING_PREVIOUS
NOT_COMPARABLE
```

Fixture chỉ thỏa failure/edge engineering evidence, không thay second E1 Reality gate.

## 9. Duplicate replay cycle

Replay lại exact same observation.

Expected:

```text
ALREADY_SEEN / idempotent
history count không tăng giả
```

Nếu count tăng mỗi lần retry, history sau này sẽ nhiễu khi watcher có retry.

M01 chưa build watcher nhưng data semantics phải sẵn sàng.

## 10. Conflict cycle

Tạo fixture:

```text
same observation_id
+ changed material value
```

Expected:

```text
CONFLICT / HUMAN_REVIEW
```

Không last-write-wins.

## 11. Out-of-order cycle

Append một valid observation có:

```text
observed_at cũ hơn latest observed_at
ingested_at mới hơn
```

Expected:

```text
record vẫn được preserve
historical query order theo observed_at
```

Đây là preparation rất quan trọng cho collection/retry sau này.

## 12. Runbook M01 final

Lưu command thực tế của implementation bạn. Một runbook tối thiểu phải chứng minh tương đương:

```text
1. run tests
2. append/query t1
3. append/query t2
4. restart
5. query/report again
6. duplicate replay
7. conflict fixture
8. out-of-order fixture
9. same report rerun
10. M00 regression tests
```

Không hard-code output chỉ để PASS.

## 13. Bot version bump

Không đổi `v0.1 → v0.2` chỉ vì bạn vừa viết 4.3.

Chỉ bump sau review ba chiều:

```text
Capability PASS
+ Reality verified E1
+ Operated
```

Nếu code chạy nhưng chưa có second E1 observation:

```text
Capability có thể PASS
Reality = pending
M01 != DONE
```

## 14. M01 final evidence chain

```text
Observation(E1, t1)
→ canonical validation
→ immutable Snapshot(t1)

Observation(E1, t2)
→ canonical validation
→ immutable Snapshot(t2)

→ restart
→ historical query
→ delta/freshness report
→ no external Action
```

Đây là thứ M02 sẽ tin cậy hơn một single current value.

## 15. Failure exercise — source biến mất ở t2

Expected:

```text
record access/missing failure
not copy t1 value
not call UNCHANGED
```

## 16. Failure exercise — restart mất history

Expected:

```text
Operated gate FAIL
```

Không được nói “unit tests vẫn pass nên M01 done”.

## 17. Failure exercise — report thay đổi theo wall clock

Nếu cùng history nhưng chạy hai lần cho freshness khác nhau vì hidden `time.Now()`:

```text
make as_of explicit
```

## 18. Evidence artifact

Lưu dưới M01 artifact:

```text
t1 E1 observation
t2 E1 observation
history before restart
history after restart
change report
as_of + policy
no-change output
changed/missing fixture output
duplicate output
conflict output
out-of-order output
deterministic rerun
M00 regression
storage trade-off note
```

## 19. Checkpoint

1. Vì sao second fixture không thay second E1 observation?
2. `UNCHANGED` có phải FAIL không?
3. Nếu source mất ở t2, có được reuse t1 value không?
4. Restart proof chứng minh gì?
5. Khi nào được bump v0.2?
6. Duplicate replay khác second observation thế nào?
7. Vì sao report cần explicit `as_of`?

<details>
<summary><strong>Đáp án / rubric</strong></summary>

- fixture chỉ là engineering evidence;
- không, unchanged là outcome quan sát hợp lệ;
- không;
- persistence không phụ thuộc process memory;
- sau Capability + Reality + Operated;
- duplicate là cùng observation, second observation là lần quan sát mới;
- để report replay/deterministic.

Blocking misconceptions:
- market phải đổi mới PASS M01;
- copy old value = new observation;
- restart không cần test;
- test PASS một mình = Mission DONE.
</details>
