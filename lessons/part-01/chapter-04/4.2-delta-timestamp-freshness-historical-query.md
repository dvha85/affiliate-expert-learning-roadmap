# Bài 4.2 — Delta, timestamp, freshness và historical query

> **Mục tiêu:** query nhiều snapshots của cùng `subject_id` theo đúng `observed_at`, phân loại delta mà không trộn `missing`, `zero`, `unchanged`, và chỉ gọi evidence `stale/current` khi có explicit `as_of + policy`.

Bài này vẫn thuộc **M01 Checkpoint 2**. Bạn đã có append-only history từ 4.1 nhưng chưa cần second real E1 cycle để PASS lesson này; fixture/canonical snapshots có thể dùng để harden semantics trước.

## 1. Có history chưa có nghĩa compare đúng

Hai dòng trong file theo thứ tự append:

```text
line 1 ingested_at = 11:00, observed_at = 10:00
line 2 ingested_at = 12:00, observed_at = 09:30
```

Nếu bạn dùng line order làm world-time order, bạn sẽ nói sai rằng observation 10:00 xảy ra trước 09:30.

Mental model:

```text
ingested_at
= arrival/storage time

observed_at
= source/world observation time
```

Historical comparison cho market evidence phải order chủ yếu theo `observed_at`.

## 2. Valid out-of-order evidence

Observation đến muộn:

```text
observed_at = 09:30
ingested_at = 12:00
```

không phải invalid chỉ vì latest snapshot trước đó có `observed_at = 10:00`.

Expected:

```text
preserve
→ mark out_of_order nếu hữu ích
→ query sort by observed_at
```

Không được silently drop late evidence.

Invalid timestamp khác late timestamp:

```text
observed_at = "banana"
→ invalid
```

## 3. Query chỉ trong cùng subject

Sai:

```text
latest Product A
vs
previous Product B
```

Đúng:

```text
history.filter(subject_id)
→ sort observed_at
→ choose previous/current
```

`product_name` không phải grouping key đáng tin.

## 4. Delta không chỉ có changed/unchanged

Per-field state tối thiểu:

```text
CHANGED
UNCHANGED
MISSING_CURRENT
MISSING_PREVIOUS
UNKNOWN
NOT_COMPARABLE
```

### CHANGED

```text
t1 price = 299000
t2 price = 259000
```

### UNCHANGED

```text
t1 price = 299000
t2 price = 299000
```

### MISSING_CURRENT

```text
t1 commission = 0.10
t2 commission = null
```

Điều này **không** phải 0% và cũng không phải unchanged.

### MISSING_PREVIOUS

```text
t1 commission = null
t2 commission = 0.10
```

Bạn biết current value nhưng không biết numeric delta từ trước.

### NOT_COMPARABLE

```text
t1 price = 299000 VND
t2 price = 12 USD
```

Không có FX/normalization policy thì không tính:

```text
12 - 299000
```

### UNKNOWN

Dùng khi semantic state không đủ để phân loại đáng tin, ví dụ source meaning thay đổi hoặc evidence conflict chưa resolve.

## 5. Observed zero vẫn là value thật

```text
t1 visible_count = 0
t2 visible_count = 0
→ UNCHANGED
```

nếu source thật sự quan sát được 0.

Nhưng:

```text
t1 visible_count = null
t2 visible_count = 0
→ MISSING_PREVIOUS
```

`null != 0` tiếp tục là invariant từ Part 00.

## 6. Delta value và delta state

Nếu compare được:

```text
previous = 299000
current = 259000
```

có thể lưu:

```text
state: CHANGED
absolute_delta: -40000
```

Nhưng `absolute_delta` chỉ có nghĩa khi units comparable.

State luôn quan trọng hơn việc ép có numeric delta.

## 7. Freshness không phải age label chung chung

Sai:

```text
age > 7 days
→ stale cho mọi field
```

Đúng:

```text
observed_at
+ as_of
+ max_age/policy cho field hoặc decision scope
→ CURRENT | STALE | UNKNOWN
```

Ví dụ:

```text
observed_at = 2026-08-31T10:00+07:00
as_of = 2026-08-31T16:00+07:00
max_age = 24h
→ CURRENT
```

Nếu không có policy:

```text
→ UNKNOWN
```

## 8. Vì sao `as_of` phải explicit?

Nếu code gọi `time.Now()` bên trong nhiều nơi:

```text
same history
→ test ở thời điểm khác
→ result có thể khác
```

Một deterministic report nên nhận:

```go
ClassifyFreshness(observedAt, asOf, maxAge)
```

Với:

```text
same observed_at
same as_of
same policy
→ same result
```

Điều này giúp replay/audit.

## 9. Future observation relative to as_of

Nếu:

```text
observed_at > as_of
```

đừng gọi nó `CURRENT`.

Đây là invalid report context hoặc clock/data issue cần fail/review rõ.

## 10. Freshness là claim-scoped

Một snapshot có thể:

```text
product_name → still useful
promotion_price → stale
commission_rule → unknown freshness
```

M01 không cần field-specific engine phức tạp, nhưng learner phải hiểu một global “snapshot fresh=true” có thể quá mạnh.

Minimal implementation có thể chỉ classify fields mà Mission đang compare và ghi policy rõ.

## 12. Test out-of-order

Store chứa:

```text
obs-10:00 ingested 10:05
obs-09:30 ingested 11:00
```

Expected query:

```text
09:30
10:00
```

không theo file append order.

## 13. Test freshness determinism

Input:

```text
observed_at = T
as_of = T + 12h
max_age = 24h
```

Expected:

```text
CURRENT
```

Rerun không phụ thuộc wall clock.

## 14. Failure exercises

### A — Missing current thành zero

Phải fail test semantic.

### B — Mixed currency vẫn tính numeric delta

Phải `NOT_COMPARABLE`/review.

### C — No policy nhưng trả CURRENT

Phải `UNKNOWN`.

### D — Append order được dùng làm observed order

Historical query phải sửa.

## 15. Evidence artifact

Lưu:

```text
historical query output
delta table
missing-vs-zero case
mixed-unit case
out-of-order case
freshness with as_of/policy
same input/as_of/policy rerun
```

## 16. Checkpoint

1. `observed_at` và `ingested_at` trả lời hai câu hỏi nào?
2. Late arrival có nên bị drop không?
3. `MISSING_CURRENT` khác `UNCHANGED` thế nào?
4. Khi nào numeric delta không hợp lệ?
5. Freshness cần những input nào?
6. Vì sao `time.Now()` hidden làm replay khó?
7. Không có freshness policy thì state nên là gì?

<details>
<summary><strong>Đáp án / rubric</strong></summary>

- observed = khi source được nhìn; ingested = khi Bot nhận/lưu;
- không nếu evidence hợp lệ;
- missing là không biết current value, unchanged là biết hai value bằng nhau;
- missing/conflict/unit mismatch;
- observed_at + as_of + policy/max_age;
- cùng history có thể cho output khác theo wall clock;
- UNKNOWN.

Blocking misconceptions:
- latest ingested = latest observed;
- missing = unchanged;
- zero = missing;
- stale là thuộc tính vĩnh viễn;
- mọi price đều comparable.
</details>
