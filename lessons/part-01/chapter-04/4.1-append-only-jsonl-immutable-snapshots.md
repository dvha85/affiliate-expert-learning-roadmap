# Bài 4.1 — Append-only JSONL và immutable snapshots

> **Mục tiêu:** biến failure “current record bị overwrite” ở M01 Checkpoint 2 thành một history store nhỏ nhưng audit được: mỗi observation được append thành snapshot bất biến, exact duplicate xử lý idempotent và conflict không được silently replace.

Bài này chỉ mở **sau khi bạn đã thử ghi đè `t1` bằng `t2` và quan sát data loss**.

## 1. Trigger — Bạn vừa mất bằng chứng gì?

Nếu implementation chỉ giữ:

```text
current.json
```

thì sau khi ghi `t2`, bạn có thể còn biết current price nhưng không còn chứng minh:

```text
price tại t1 là gì?
change xảy ra giữa observations nào?
reason/decision cũ dựa trên snapshot nào?
```

Mental model:

```text
CURRENT STATE
không thay thế được
HISTORY
```

## 2. Snapshot là gì?

Một Snapshot trong M01 là một observation đã đi qua canonical ingest và được freeze để audit.

```text
Canonical Observation
→ serialize/copy
→ Snapshot
```

Snapshot phải giữ tối thiểu:

```text
subject_id
observation_id
observed_at
ingested_at
provenance
normalized values
missing state
```

Một snapshot không phải “Product hiện tại”. Nó là **bằng chứng về một lần quan sát cụ thể**.

## 3. Vì sao append-only?

Thay vì:

```text
read current
→ modify
→ overwrite
```

M01 dùng:

```text
append snapshot t1
append snapshot t2
append snapshot t3
```

Canonical learner store:

```text
data/history.jsonl
```

Mỗi dòng là một JSON object độc lập.

Ví dụ:

```json
{"subject_id":"P-A","observation_id":"OBS-A-1","observed_at":"2026-08-31T10:00:00+07:00","price":299000}
{"subject_id":"P-A","observation_id":"OBS-A-2","observed_at":"2026-09-02T10:00:00+07:00","price":259000}
```

JSONL được chọn vì learner có thể nhìn bằng mắt, append, reload và test restart mà chưa cần database.

## 4. Immutable nghĩa là gì?

Sau khi snapshot đã được append thành công:

```text
mutation ở object caller
≠ history cũ thay đổi
```

Failure phổ biến trong memory store:

```go
history = append(history, recordPointer)
```

rồi caller sửa object mà history cũng đổi theo.

Safe mental model:

```text
append serialized/copy value
not shared mutable alias
```

Bạn không cần học deep-copy framework. Chỉ cần test rằng thay input sau append không làm snapshot cũ đổi.

## 5. Exact duplicate khác conflict

### Exact duplicate

```text
same observation_id
+ same canonical content
```

Thường xảy ra khi replay/import lại cùng file.

Expected:

```text
ALREADY_SEEN / idempotent
history count không tăng giả
```

### Conflict

```text
same observation_id
+ different canonical content
```

Expected:

```text
CONFLICT
→ reject conflicting append / HUMAN_REVIEW
```

Không được:

```text
last write wins
```

vì như vậy evidence cũ bị thay mà không để lại dấu vết.

## 6. Same subject + same observed_at conflict

Hai observations:

```text
subject_id = P-A
observed_at = 10:00
price = 299000
```

và:

```text
subject_id = P-A
observed_at = 10:00
price = 259000
```

có thể là source conflict, capture error hoặc identity issue.

M01 không cần tự quyết record nào đúng.

Expected:

```text
HUMAN_REVIEW / conflict artifact
```

## 7. Try First — Viết test failure trước

Trước implementation, viết test theo behavior:

```text
append t1
append t2
→ history length = 2
→ t1 vẫn còn nguyên
```

Tiếp theo:

```text
append exact duplicate t2
→ history length không đổi
```

và:

```text
same observation_id + different content
→ conflict
```

Hãy nhìn test fail trước khi implement để chứng minh test thật sự bảo vệ semantics.

## 8. Minimal store API

Một shape đủ dùng có thể là:

```go
type Store interface {
    Append(snapshot Snapshot) (AppendResult, error)
    LoadAll() ([]Snapshot, error)
}
```

Nhưng **interface không phải mục tiêu**. Nếu concrete `JSONLStore` đơn giản hơn cho learner, dùng concrete type trước.

Điều cần chứng minh là behavior, không phải pattern architecture.

## 9. Write failure phải fail rõ

Append-only không có nghĩa write luôn thành công.

Nếu:

```text
disk error
permission error
partial write
```

thì không được in:

```text
snapshot saved
```

nếu chưa save thành công.

M01 chỉ cần error rõ và testable; chưa cần transaction system production.

## 10. Corrupt/truncated line

History JSONL có thể chứa một dòng hỏng.

Không được silently skip rồi báo:

```text
history valid
```

Safe choices ở M01:

```text
fail rõ + line number
```

hoặc:

```text
quarantine rõ + report incomplete history
```

Quan trọng là corruption không biến mất khỏi audit.

## 11. Apply — Chuyển overwrite implementation sang append

Lưu before:

```text
store_mode: overwrite
history available after t2: only t2
```

Sau đó implement append-only JSONL.

After:

```text
store_mode: append_only_jsonl
snapshots: 2
snapshot t1 preserved: yes
snapshot t2 preserved: yes
```

Expected conflict/review.

Expected fail/quarantine rõ.

Lưu:

```text

```

Không cần PostgreSQL.

## 14. Checkpoint

1. Current state khác history thế nào?
2. Vì sao append-only hỗ trợ audit?
3. Append-only có tự làm data đúng không?
4. Exact duplicate khác conflict thế nào?
5. Vì sao “last write wins” nguy hiểm cho evidence?
6. Vì sao object mutation sau append phải không đổi snapshot?

<details>
<summary><strong>Đáp án / rubric</strong></summary>

- current chỉ là state gần nhất; history giữ chuỗi evidence;
- append giữ snapshot cũ để truy lại;
- không, bad evidence vẫn có thể được append nếu validation sai;
- duplicate = cùng identity/content; conflict = cùng identity nhưng nội dung khác;
- nó overwrite evidence không minh bạch;
- vì snapshot phải immutable sau persistence.

Blocking misconceptions:
- JSONL = database production;
- append-only = không cần validation;
- duplicate nào cũng là conflict;
- record mới được phép sửa record cũ silently.
</details>

