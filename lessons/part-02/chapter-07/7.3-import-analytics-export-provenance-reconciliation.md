# Bài 7.3 — Import analytics/export, provenance và reconciliation

> Pull bài này khi M01 có export/dashboard nhưng metric, timezone, scope hoặc source conflict chưa rõ.

## Try First — 15 phút

Đọc một source permitted read-only và ghi không sửa dữ liệu:

```text
reporting_source / scope / timezone / observed_at
tracking or campaign reference / window
metric label / raw status / limitation
```

## Observe — tìm gap

Hai số cùng tên không tự comparable. Hỏi: có cùng source, scope, attribution, window, config và refresh time không?

## Minimum Knowledge

Provenance trả lời dữ liệu đến từ đâu và đọc khi nào. Reconciliation không có nghĩa ép số khớp; result hợp lệ là `MATCHED`, `EXPLAINED_DIFFERENCE`, `CONFLICTING` hoặc `INSUFFICIENT_CONTEXT`.

## Apply — quay lại M01

Tạo MeasurementContext tối thiểu, map field cần thiết vào snapshot, preserve original reference và ghi reconciliation state. Bắt đầu bằng manual/read-only import; chỉ thêm n8n/import workflow khi repeated plumbing tạo bottleneck thật. Dù dùng cách nào, canonical validation vẫn phải reject payload thiếu context.

## Failure Case

- Copy CSV vào repo hoặc prompt/log.
- Gộp dashboard click với network conversion mà không có mapping.
- Chọn số “đẹp hơn” khi source conflict.

## Evidence

Giữ raw export local, commit chỉ redacted summary/checksum/reference. Ghi importer version hoặc manual procedure để lần đọc sau tái lập được.

## Explain-back

Giải thích được số nào là canonical cho claim hẹp của bạn, số nào conflict, và limitation nào chưa được giải quyết.
